# 智能工单管理系统 - 项目章程

## 1. 项目基本信息
- 项目名称：智能工单管理系统
- 项目类型：个人项目 / 轻量级内部工具
- 项目角色：独立开发（兼项目经理、开发、测试、运维）
- 项目周期：【2026.09 - 2026.11，共 8 周】
- 技术栈：
  - Java 21、Spring Boot 3、Spring Security、MyBatis-Plus、MySQL 8、Redis、Springdoc OpenAPI、JUnit 5 + Mockito
  - Python 3.11、FastAPI、LangChain / LangGraph、大模型 API
  - Docker Compose、Nginx

## 2. 项目背景
客服团队日常处理大量用户工单，存在以下问题：
1. 工单分类靠人工阅读，效率低、易出错。
2. 派单依赖人工判断，无法根据客服负载自动分配。
3. 工单状态不透明，用户和主管无法实时追踪进度。
4. 大量重复问题需要客服重复回复，缺少辅助建议。
5. 通用大模型无法直接操作内部业务系统，直接调用又存在越权、误操作和无法审计的问题。

因此，本项目目标是：用 Java 构建稳定、可控的工单管理核心后端，用 Python Agent 作为辅助能力，实现工单创建、自动分类、自动派单、状态流转、回复建议、审计和统计的闭环。

## 3. 项目目标
### 3.1 业务目标
- 实现工单全生命周期管理：创建 → 分类 → 派单 → 处理 → 解决 → 关闭。
- 减少人工分类和派单耗时，提升客服处理效率。
- 提供工单统计和审计能力，便于追踪和优化。

### 3.2 技术目标
- 用 Java 实现核心业务：认证授权、工单 CRUD、状态机、自动派单、审计、统计。
- 用 Python Agent 实现辅助能力：工单分类、回复建议。
- Java 通过 HTTP 调用 Python Agent，设置超时、降级和审计，保证 AI 故障不影响主流程。
- 使用 Docker Compose 一键部署，核心业务有单元测试。

### 3.3 个人目标
- 巩固 Java 后端开发能力：Spring Boot、MySQL、Redis、权限、事务、幂等、异常处理。
- 了解 Agent 应用落地：Function Calling、工具调用安全、降级策略。
- 形成完整项目文档，作为简历和面试素材。

## 4. 项目范围
### 4.1 做什么
- 认证授权：JWT 登录、RBAC 角色权限。
- 工单管理：创建、列表分页、详情、编辑、状态流转、优先级。
- 自动派单：按工单类型匹配客服组，结合客服负载分配。
- 审计日志：记录工单操作、AI 调用、派单结果。
- 数据统计：工单数量、类型分布、平均处理时长、客服工作量。
- AI 辅助：工单自动分类、回复建议生成。
- 稳定性：统一响应、统一异常、traceId、接口幂等、Redis 缓存、限流降级。
- 部署：Docker Compose 编排 Java + Python + MySQL + Redis。

### 4.2 不做什么
- 不做微服务、Kafka、K8s。
- 不做多租户、SaaS 化。
- 不做高并发、百万级流量。
- 不做复杂前端，只做简易管理台或 Postman 接口演示。
- 不做工作流引擎、规则引擎。
- 不让 AI 直接操作核心业务，AI 只做辅助建议。

## 10. 风险与应对
| 风险          | 影响       | 应对                                         |
