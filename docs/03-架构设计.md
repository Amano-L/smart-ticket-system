# 智能工单管理系统 - 架构设计

## 1. 架构目标与原则
目标：
- Java 后端保证核心业务稳定、可控、可审计。
- Python Agent 提供 AI 辅助能力，可替换、可降级。
- 系统轻量，Docker Compose 一键部署。
- 结构清晰，便于个人开发和面试讲解。

原则：
- Java 主后端，Python 辅助。
- AI 不直接操作核心业务。
- 核心业务不依赖 AI。
- 先保证正确性，再考虑性能。
- 不引入超出个人项目需求的组件。

## 2. 总体架构
客户端（浏览器 / Postman / 简易管理台）
→ Java Spring Boot 后端
→ MySQL / Redis
→ Python Agent 服务（FastAPI + LangChain）
→ 大模型 API

Java 后端内部模块：认证授权、工单管理、派单、审计日志、数据统计、系统管理、AI 客户端、基础设施（统一异常 / 统一响应 / traceId / 幂等 / 限流）。

## 4. 模块划分

### 4.1 Java 后端模块
- 认证授权模块：登录、JWT、RBAC、接口鉴权。
- 工单模块：创建、列表、详情、编辑、状态机。
- 派单模块：类型匹配、负载分配、手动改派。
- 审计模块：操作审计、AI 调用审计、日志查询。
- 统计模块：趋势、分布、时长、工作量。
- AI 客户端模块：调用 Python Agent、超时、重试、降级、审计。
- 基础设施模块：统一响应、统一异常、traceId、幂等、限流、Redis。

### 4.2 Python Agent 模块
- 分类 Agent：输入工单文本，输出分类标签。
- 回复建议 Agent：输入工单内容，输出建议话术。
- 提示词管理：集中管理提示词模板。
- 模型调用：调用大模型 API，处理超时和异常。
- 健康检查：提供健康检查接口。

## 5. 核心流程

### 5.1 创建工单流程
1. 用户提交工单。
2. Java 保存工单，状态为“待处理”。
3. Java 调用 Python `/agent/classify`，超时 2 秒。
4. Python 调用大模型，返回分类标签。
5. 分类失败时，Java 走规则分类，兜底 UNKNOWN。
6. Java 按类型和客服负载派单。
7. Java 保存派单记录和审计日志。
8. 返回工单编号和状态。

### 5.2 客服处理流程
1. 客服查看工单详情。
2. Java 调用 Python `/agent/reply-suggest`，超时 2 秒。
3. Python 调用大模型，返回建议。
4. Java 展示建议给客服。
5. 客服确认或修改后发送。
6. Java 保存回复、流转记录、审计日志。

### 5.3 AI 降级流程
1. Java 请求 Python `/agent/classify`。
2. Python 超时或异常。
3. Java 走规则分类。
4. Java 记录 AI 调用失败和降级。
5. Java 继续派单，主流程不受影响。

## 6. 数据库设计概要

### 6.1 核心表
| 表名          | 说明           |
| :------------ | :------------- |
| sys_user      | 用户表         |
| sys_role      | 角色表         |
| sys_user_role | 用户角色关联表 |
| ticket        | 工单表         |
| ticket_flow   | 工单流转记录表 |
| agent_load    | 客服负载表     |
| audit_log     | 审计日志表     |
| ai_call_log   | AI 调用记录表  |

### 6.2 关键字段
ticket：id、ticket_no、title、content、type、status、priority、creator_id、assignee_id、created_at、updated_at。

ticket_flow：id、ticket_id、from_status、to_status、operator_id、remark、created_at。

agent_load：id、user_id、current_count、max_count、updated_at。

audit_log：id、user_id、action、target_type、target_id、result、detail、trace_id、created_at。

ai_call_log：id、ticket_id、call_type、model、cost_ms、success、fallback、request、response、created_at。

### 6.3 索引设计
- ticket：ticket_no 唯一索引，status + created_at 联合索引，assignee_id + status 联合索引。
- ticket_flow：ticket_id 索引。
- audit_log：trace_id 索引，target_type + target_id 索引。
- ai_call_log：ticket_id 索引，created_at 索引。

## 7. API 设计规范

### 7.1 统一响应
成功：code=0, message=success, data, traceId。
分页：data 包含 list、total、page、size。
失败：code 非 0，message 描述错误，data=null，traceId。

### 7.2 统一异常码
| code | 说明                                 |
| :--- | :----------------------------------- |
| 0    | 成功                                 |
| 400  | 参数错误                             |
| 401  | 未登录或 Token 失效                  |
| 403  | 无权限                               |
| 404  | 资源不存在                           |
| 409  | 状态冲突（如非法状态流转、重复提交） |
| 429  | 请求过于频繁                         |
| 500  | 系统异常                             |
| 1001 | 用户名或密码错误                     |
| 1002 | 账号已禁用                           |
| 2001 | 工单不存在                           |
| 2002 | 工单状态不允许此操作                 |
| 2003 | 重复提交工单                         |
| 3001 | 无可用客服                           |
| 4001 | AI 服务调用失败（已降级）            |

## 8. Python Agent 服务设计

### 8.1 接口
| 方法 | 路径                 | 说明     |
| :--- | :------------------- | :------- |
| GET  | /health              | 健康检查 |
| POST | /agent/classify      | 工单分类 |
| POST | /agent/reply-suggest | 回复建议 |

说明：Python 服务只暴露以上三个接口，仅允许 Java 后端通过内网调用。Java 对外只暴露 `/api/ai/suggest/{ticketId}`，由 Java 内部通过 RestClient 调用 Python 的 `/agent/classify` 和 `/agent/reply-suggest`。

### 8.2 分类 Agent
输入：ticketId、title、content。  
输出：type、confidence、fallback。  
超时：2 秒。  
失败：返回错误码，Java 侧走规则分类，兜底 UNKNOWN。

### 8.3 回复建议 Agent
输入：ticketId、content、history。  
输出：suggestion、references、fallback。  
失败：Java 侧不展示建议，不影响客服手动回复。

### 8.4 安全
- 只允许 Java 后端调用，内网访问。
- 参数校验。
- 提示词注入基础防护。
- 不直接操作数据库和业务接口。

## 9. 安全设计
- JWT + RBAC。
- 接口级权限控制。
- 参数校验和统一异常。
- 审计日志不可篡改。
- AI 服务不暴露公网。
- 敏感配置使用环境变量。
- 限流和幂等防止重复提交。

## 10. 稳定性设计
- 统一异常处理。
- traceId 全链路追踪。
- 接口幂等：创建工单使用 X-Request-Id。
- Redis 缓存客服负载。
- AI 调用超时 2 秒，失败降级。
- 核心接口限流。
- 健康检查和日志。

## 11. 部署架构
Docker Compose 编排：
- java-backend：8080
- python-agent：8000
- mysql：3306
- redis：6379
- nginx：80（可选）

## 12. 监控与日志
- 日志：JSON 格式，包含 traceId。
- 监控：接口耗时、错误率、AI 调用成功率、降级次数。
- 健康检查：Java /actuator/health，Python /health。
- 审计：操作日志、AI 调用日志。

## 13. 扩展性考虑
- AI 服务可替换为 Spring AI / LangChain4j。
- 分类模型可替换。
- 可增加知识库 RAG。
- 可增加消息通知。
- 可迁移到 K8s，但本期不做。
