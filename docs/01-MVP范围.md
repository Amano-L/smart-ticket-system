# 智能工单管理系统 - MVP 范围

## 1. MVP 目标
用 8 周时间完成一个可演示、可讲清楚的工单管理闭环：
用户提交工单 → Java 后端创建工单 → Python Agent 辅助分类 → Java 自动派单 → 客服处理 → AI 回复建议 → 状态流转 → 审计与统计。

核心原则：
- Java 后端是主体，负责稳定业务。
- Python Agent 是辅助，负责分类和回复建议。
- AI 可失败、可降级，不影响主流程。

## 2. 用户角色
| 角色     | 编码       | 权限                                                         |
| :------- | :--------- | :----------------------------------------------------------- |
| 普通用户 | USER       | 创建工单、查看自己的工单、补充信息                           |
| 客服     | AGENT      | 查看分配给自己的工单、处理、回复、改状态、查看 AI 建议       |
| 客服主管 | SUPERVISOR | 查看所有工单、手动派单、查看统计                             |
| 管理员   | ADMIN      | 用户管理、角色管理、审计日志、系统配置、查看全部工单、查看统计 |

## 3. 核心业务流程
1. 用户提交工单（标题、内容、优先级）。
2. Java 创建工单，状态为“待处理”。
3. Java 调用 Python Agent 进行工单分类，失败则走规则分类。
4. Java 根据分类和客服负载自动派单。
5. 客服查看工单，Java 调用 Python Agent 生成回复建议。
6. 客服确认后回复，工单状态流转。
7. 所有操作写入审计日志。
8. 主管查看统计看板。

## 4. 工单状态机
- 待处理（0） → 处理中（1）
- 处理中（1） → 已解决（2）
- 已解决（2） → 已关闭（3）
- 已关闭（3） → 不可再流转
- 禁止非法流转，例如：待处理 → 已关闭、已关闭 → 处理中。

## 6. 功能范围（MoSCoW）

### Must（必须做）
- JWT 登录 + RBAC 权限。
- 工单创建、列表分页、详情、编辑。
- 工单状态流转 + 流转记录。
- 审计日志：记录操作人、操作类型、时间、结果。
- 统一响应、统一异常、traceId。
- MySQL 8 张核心表设计与建表。
- Docker Compose 基础编排：Java + MySQL + Redis。

### Should（应该做）
- 自动派单：按类型匹配客服组，按负载分配。
- Redis 缓存：客服负载计数、热点工单缓存。
- 数据统计：工单数量、类型分布、平均处理时长、客服工作量。
- 接口幂等：防止重复提交工单。
- 限流降级：核心接口限流，AI 调用超时降级。
- JUnit 单元测试：核心 Service 覆盖。

### Could（可以做）
- Python Agent 工单分类。
- Python Agent 回复建议。
- 简易管理台页面。
- 回复建议附带历史工单引用。
- AI 调用审计：记录模型、耗时、结果、是否降级。
- 客服可人工修正 AI 分类结果。

### Won't（本期不做）
- 微服务、Kafka、K8s。
- 多租户、SaaS。
- 高并发、百万请求。
- 复杂前端、工作流引擎。
- AI 直接操作核心业务。
- 多 Agent 复杂编排。

## 8. AI 辅助范围与降级策略
### 8.1 AI 分类
- 输入：工单标题 + 内容。
- 输出：分类标签（REFUND / TECH / COMPLAINT / CONSULT）。
- 调用方式：Java 通过 RestClient 调用 Python `/agent/classify`。
- 超时：2 秒。
- 失败降级：走规则分类，例如关键词匹配，分类为 UNKNOWN。
- 审计：记录是否 AI 分类、耗时、结果、是否降级。

### 8.2 AI 回复建议
- 输入：工单内容 + 历史相似工单。
- 输出：建议回复话术。
- 调用方式：Java 通过 RestClient 调用 Python `/agent/reply-suggest`。
- 失败降级：不展示建议，客服手动回复。
- 安全：AI 只生成建议，客服确认后才发送。

## 9. 验收标准
### 9.1 功能验收
- 用户能登录并创建工单。
- 工单能正确分类和派单。
- 客服能处理工单并流转状态。
- 非法状态流转被拦截。
- 审计日志完整记录。
- 统计接口返回正确数据。

### 9.2 技术验收
- 13+ REST API 可用，OpenAPI 文档完整。
- JWT + RBAC 权限生效。
- 核心接口有单元测试，覆盖率 ≥ 70%。
- 接口幂等生效，重复提交不产生重复工单。
- AI 服务关闭后，工单主流程仍可用。

### 9.3 AI 验收
- 50 条评测集，分类准确率 ≥ 85%。
- AI 调用超时 2 秒内降级。
- AI 调用记录写入审计日志。

### 9.4 部署验收
- Docker Compose 一键启动。
- 健康检查通过。
- 日志可查看，traceId 可追踪。
